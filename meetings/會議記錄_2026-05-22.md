## 3) 討論摘要

### 主題1｜阿全 codex 上線進度匯報

**士豪向彥偉解釋**今天 5/22 已完成的內容、對照 5/19 會議定的待辦：

- **capability lock**：codex 原生工具（改檔、看檔、修改檔案、上網）全砍掉、只開公司用的 MCP tool
- **MCP 工具**：阿全現在能查會議記錄、工作紀錄（從 cwsoft-project-tracker）、工程師知識庫、客服 SOP 知識庫、SQL Server 客戶資料、加扣月租 / 簡訊點數、出月租 / 週邊產品報價單
- **安全機制**：寫入動作（加扣點等）codex 自己會寫進 notebook、半自動、人介入確認後才寫入「不會失控」
- **per-user session**：每個人對話獨立、3 人有 3 條不同 session、context 切開、各人經驗會彙整到共享 notebook 跨人累積（= 5/19 會議講的「同時多人講話會混茶」問題解了）
- **alias 測試機制（dev 端新增）**：士豪今天加的、開發版 LINE 帳號訊息前綴 `@xxx` 就可以模擬不同 user_id、一個帳號可以測試 n 個人進來的用法。**未來客服上線時可以模擬 n 個不同客戶與阿全對話測試**
- **客服 AI（cs_codex）也會用這套**——目前沒有改 GTP 知識庫的權限、需求都會先寫進 notebook

### 主題2｜工作紀錄 + bonus 制度 + 周休3日願景（彥偉訓話）

彥偉藉羿宏「忘記要記工作紀錄」插話、講了一段對團隊治理跟願景的整理：

- **明年起、用 AI 寫工作紀錄 + 評估產出**：以前沒 AI 很難做到、現在可以了。每天改了什麼、做了什麼、簡單記
- **bonus 評估邏輯**：「我看你**到底 AI 產出了多少**、而不是看你工作了多少」——以 AI 產出的東西為單位、不看人在公司的時間
- **公司方向 = 周休 3 日 + 產出多 + 服務品質高**——「大家可以輕鬆一點過生活、把產值拉上去、一起賺錢」
- **目前狀態**：今年之前公司其實是彥偉自己貼錢、量還不夠、做不出真正能賺錢的東西。今年起進階行銷系統可賣錢、確認可行（已有客戶付款）
- **羿宏的弱項**：「如果沒有請 AI 做的話、你的 bonus 比例會相差很多」——彥偉直接點出羿宏要主動用 AI summary 自己的工作

對士豪：「我看的出來已經開始賣了、我知道你有做。你要試著表達這些東西。」

### 主題3｜POS 會員點數紀錄系統（羿宏設計討論）

羿宏報告當前點數系統的設計：

**核心問題**：銷售單可以修改 / 刪除、點數系統要怎麼補正？

| 場景 | 設計 |
|---|---|
| 單據成立 → 加點 | 正常加 |
| 單據修改 → 點數重算 | DB 兩筆（修改前、修改後）、前端壓成一筆顯示「合併了 N 筆」 |
| 單據刪除 → 扣點 | 多一筆「點數扣除」紀錄、按時間排序 |
| 修改單據跨「點數活動期間」（如雙倍送）| 按該單**當下時間點**的點數規則、不是按修改當下 |
| 商品改類別 | 改到/改自「行動電話」這類關鍵類別要提示警告（其他類別改不影響） |

**彥偉要求羿宏做一份「客戶可看的規則文件」**：

- 把修改單據 / 刪除單據 / 改類別 等所有規則整理成可給客戶的文件
- 賣的時候給客戶看「你看我們什麼細節都想到」當行銷材料
- 用**互動式網頁**呈現（不是 md raw 文件、不是流程圖）

**新增商品時的點數預設值**（羿宏提的待補功能）：

- 例：手機類設定為 80 點、新增一個手機類商品時應該預設帶 80 點進去
- 「現在才有、還來得及（人家還沒上線）」

### 主題4｜POS UI 畫面配置（會員等級調整 vs 點數紀錄）

羿宏展示一個畫面、彥偉提出配置改動：

- 當前：點數紀錄面板在會員資料下方、寬度被拉得很寬但內容只有一點點
- 彥偉建議：把點數紀錄面板**移到右邊**（左邊放主體會員資料、右邊放消費歷史 / 點數紀錄）
- 理由：「每個人的畫面大部分不是 4:3 就是 16:9、拉成直的不對」

**進階建議**：用 AI 自動排版

- 給 AI 一些畫面配置規範（哪些欄位通常是地址比較長之類）、AI 自動判斷怎麼擺
- 彥偉舉例：他看過 AI 一次產出 3 張 thumbnail、然後丟回 AI 問「你覺得哪個點擊率最高」、結果跟人投票差不多
- 「規範可以慢慢改、AI 應該有辦法拉出 1 個漂亮的畫面」

### 主題5｜進階行銷系統介紹文件需求（彥偉）

彥偉要的不是給工程師看的 md 規格、是**給客戶看的精簡 marketing 文件**：

- 現在士豪寫了 1000 多行的 md 規則檔（AI 寫的）——彥偉覺得「廢話太多、人看不下去」
- 要把它**化繁為簡**做成「互動式網頁」（html、人友善、不是流程圖）
- 進入 = 給客戶看「我們現在的設計是這樣、你有沒有意見?」
- 「以前是裝有料、現在是真的太多、要濃縮」

兩種 doc 區分清楚：
- **md 詳細版**：給 AI 看的、用來複製 / 參考 / debug
- **html 視覺化版**：給人類客戶看的、marketing 用

### 主題8｜進階行銷會員系統重構（士豪）

當前架構問題：

- **目前是「分店視角」**——站在「這家分店有綁定哪些會員」的角度看
- **彥偉要的是「公司視角」**——跨多分店 / 跨多 LINE OA、看公司所有會員、可以針對某一群會員發特別訊息
- **跨 OA 群發**：一個會員可能在多家分店的 OA 都加過、最後互動的那個 OA 就是我們發訊息給他的途徑（「每個會員多 1 個欄位記他最後互動的 OA」）

決議：**打掉重做**——彥偉：

> 「現在打掉重做我有 SoS（OK）我只是改 1 個角度在看這件事。現在都是 AI 在做、可以打掉。」
> 「我每個月 2000 額度給你燒、你到禮拜五我都已經燒完了。我們與其思考 1 個月 2000-3000 的事情、那讓工程提前快半年完成、到底有什麼不好？」
> 「這個錢我覺得投得很值得。」

→ **AI 燒錢額度可以加碼**、優先換工程速度。
